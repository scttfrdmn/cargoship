# v0.6.2 Advanced Transporters CLI Integration - Architecture Design

**Issue**: #37, #44
**Version**: v0.6.2
**Status**: Design Phase
**Author**: Claude Code
**Date**: 2025-12-14

---

## Executive Summary

This design document outlines the architecture for integrating CargoShip's advanced S3 transporters directly into the CLI, enabling streaming uploads to S3 without local archive creation. This change will allow CargoShip to leverage its sophisticated network optimization code (BBR/CUBIC, adaptive staging, bandwidth optimization, etc.) that currently exists but is unused by the CLI.

**Key Objective**: Make the CLI use the same high-performance transporter architecture that GhostShip uses successfully, eliminating the current rclone dependency and enabling direct streaming to S3.

---

## Current State Analysis

### What Works Today (GhostShip Pattern)

GhostShip demonstrates the correct architecture:

```go
// pkg/launch/ghost_ship.go & local_archiver.go
LocalArchiver → Transporter (Staging/Adaptive/Optimized) → S3

Features:
✓ SetTransporter() - Configure S3 transporter
✓ SetOptimizer() - Enable S3 optimization features
✓ Streaming uploads - No local archive creation
✓ Progress callbacks - Real-time upload tracking
✓ Worker pools - Concurrent archival jobs
✓ Retry logic - Automatic retry with backoff
```

### What's Wrong Today (CLI Pattern)

The CLI bypasses all advanced S3 code:

```bash
# Current flow (WRONG)
cargoship upload /data s3://bucket/path
    ↓
Create local tar.zst archive (uses disk space)
    ↓
Upload via rclone (bypasses ALL CargoShip optimization)
    ↓
Result: Slower, uses disk, defeats project purpose
```

**Problems:**
- ❌ Uses local disk space for temporary archives
- ❌ Doesn't leverage BBR/CUBIC congestion control
- ❌ Doesn't use adaptive staging
- ❌ Doesn't use chunk prediction
- ❌ Doesn't use bandwidth optimization
- ❌ Loses in competitive benchmarks
- ❌ Defeats the entire purpose of CargoShip

## Proposed Architecture

### High-Level Flow

```
CLI Command
    ↓
Transport Layer Factory (NEW)
    ↓
    ├─> Basic Transporter (simple multipart)
    ├─> Staging Transporter (with deduplication) [DEFAULT]
    ├─> Adaptive Transporter (parameter tuning)
    └─> Optimized Transporter (network-aware)
    ↓
Streaming Archiver (Reuse LocalArchiver pattern)
    ↓
    ├─> File Scanner
    ├─> Tar Stream Generator
    ├─> Compression (zstd/gzip/none)
    └─> Progress Tracking
    ↓
S3 Upload (via selected transporter)
    ↓
    ├─> BBR/CUBIC Congestion Control
    ├─> Adaptive Staging
    ├─> Chunk Prediction
    ├─> Bandwidth Optimization
    ├─> RTT Estimation
    └─> Pipeline Optimization
    ↓
Result + Metrics
```

### Component Architecture

#### 1. Transport Layer Factory (NEW)

**Location**: `pkg/transport/factory.go`

```go
package transport

type TransporterType string

const (
    TransporterBasic     TransporterType = "basic"
    TransporterStaging   TransporterType = "staging"   // DEFAULT
    TransporterAdaptive  TransporterType = "adaptive"
    TransporterOptimized TransporterType = "optimized"
)

type FactoryConfig struct {
    Type         TransporterType
    S3Config     awsconfig.S3Config
    S3Client     *s3.Client
    EnableOptimization bool  // Enable BBR/CUBIC, BDP, etc.

    // Optimization features (when EnableOptimization=true)
    CongestionControl  string  // "bbr", "cubic", "auto"
    EnableStaging      bool    // Adaptive staging
    EnablePrediction   bool    // ML chunk prediction
    EnableBDP          bool    // Bandwidth-Delay Product optimization
}

func NewTransporter(config FactoryConfig) (interface{}, error)
```

**Responsibilities:**
- Create appropriate transporter based on user selection
- Configure optimization features (BBR/CUBIC, staging, etc.)
- Provide sensible defaults (Staging transporter, all optimizations enabled)
- Validate configuration before creating transporter

#### 2. Streaming Archiver Adapter (NEW)

**Location**: `pkg/cli/archiver.go`

Adapts the existing `LocalArchiver` pattern for CLI use:

```go
package cli

type StreamingArchiver struct {
    archiver    *launch.LocalArchiver
    transporter interface{}
    optimizer   *s3optimization.S3Optimizer
    progress    *ProgressTracker
}

func NewStreamingArchiver(config ArchiverConfig) (*StreamingArchiver, error)

func (sa *StreamingArchiver) ArchiveDirectory(
    ctx context.Context,
    sourceDir string,
    s3Destination string,
) (*ArchiveResult, error)
```

**Responsibilities:**
- Wrap LocalArchiver for CLI context
- Handle directory scanning
- Create streaming tar archive
- Apply compression
- Track progress for CLI display
- Report results and metrics

#### 3. CLI Integration

**Location**: `cmd/cargoship/cmd/upload.go` (MODIFIED)

New command structure:

```bash
cargoship upload [SOURCE] [S3_DESTINATION] [flags]

# Examples:
cargoship upload /data s3://bucket/dataset
cargoship upload /data s3://bucket/dataset --transporter staging
cargoship upload /data s3://bucket/dataset --transporter adaptive --no-optimization
cargoship upload file.tar.gz s3://bucket/file.tar.gz --transporter basic
```

## CLI Interface Specification

### New Flags

#### Primary Flags

```bash
--transporter <type>
    Type of S3 transporter to use
    Values: basic, staging, adaptive, optimized
    Default: staging

    basic     - Simple AWS SDK multipart upload
    staging   - Full staging with deduplication (RECOMMENDED)
    adaptive  - Adaptive parameter tuning based on network
    optimized - Network-optimized with congestion control

--s3-destination <s3://bucket/prefix>
    (Alternative to positional argument)
    S3 destination URL
    Format: s3://bucket-name/optional/prefix

--storage-class <class>
    S3 storage class (unchanged)
    Values: STANDARD, STANDARD_IA, GLACIER, DEEP_ARCHIVE, etc.
    Default: INTELLIGENT_TIERING
```

#### Optimization Flags

```bash
--optimization / --no-optimization
    Enable/disable all optimization features
    Default: enabled
    When enabled, activates: BBR/CUBIC, staging, BDP, prediction

--congestion-control <algorithm>
    Congestion control algorithm
    Values: bbr, cubic, auto
    Default: auto (BBR preferred, fallback to CUBIC)

--disable-staging
    Disable adaptive staging (reduces memory usage)
    Default: false (staging enabled)

--disable-prediction
    Disable ML-based chunk size prediction
    Default: false (prediction enabled)

--disable-bdp
    Disable Bandwidth-Delay Product optimization
    Default: false (BDP enabled)
```

#### Streaming & Archive Flags

```bash
--compression <type>
    Compression algorithm
    Values: zstd, gzip, none
    Default: zstd

--compression-level <level>
    Compression level (algorithm-specific)
    zstd: 1-22 (default: 3)
    gzip: 1-9 (default: 6)

--archive-format <format>
    Archive format for directory uploads
    Values: tar, tar.gz, tar.zst
    Default: tar.zst

--no-archive
    Upload files individually (no tar archive)
    Only valid for directory uploads
    Default: false (create archive)
```

#### Progress & Monitoring

```bash
--progress / --no-progress
    Enable/disable progress display
    Default: enabled (auto-disabled if not TTY)

--progress-interval <duration>
    Progress update interval
    Default: 100ms
    Format: 100ms, 1s, etc.

--json-output
    Output results as JSON (disables progress display)
    Default: false

--metrics
    Display detailed transfer metrics on completion
    Default: false
```

### Command Modes

#### Mode 1: Directory Upload (Streaming Archive)

```bash
cargoship upload /my/data s3://bucket/dataset

Flow:
1. Scan directory
2. Create streaming tar archive
3. Compress on-the-fly (zstd)
4. Upload directly to S3 via transporter
5. NO local file creation
```

#### Mode 2: Single File Upload

```bash
cargoship upload /path/to/file.tar.gz s3://bucket/file.tar.gz

Flow:
1. Detect single file
2. Stream file directly to S3 via transporter
3. No archive creation (already a file)
```

#### Mode 3: Individual File Upload (No Archive)

```bash
cargoship upload /my/data s3://bucket/dataset --no-archive

Flow:
1. Scan directory
2. Upload each file individually to S3
3. Preserve directory structure in S3 keys
4. Parallel uploads via worker pool
```

### Key Technical Details

#### 1. Zero Local Disk Usage

```go
// Create io.Pipe for streaming
pipeReader, pipeWriter := io.Pipe()

// Goroutine 1: Generate tar archive
go func() {
    tarWriter := tar.NewWriter(pipeWriter)
    // Write files to tar...
    tarWriter.Close()
    pipeWriter.Close()
}()

// Goroutine 2: Compress stream
compressedReader := compressStream(pipeReader, compressionType)

// Main goroutine: Upload to S3
transporter.Upload(ctx, Archive{
    Reader: compressedReader,
    Key: s3Key,
    ...
})
```

**Benefit**: Entire operation happens in memory using pipes. No temporary files created.

#### 2. Progress Tracking

```go
// Wrap reader with progress tracking
progressReader := &ProgressReader{
    reader: compressedReader,
    onProgress: func(bytesRead int64) {
        progress.Update(bytesRead)
    },
}

// Progress display (concurrent)
go progress.Display() // Updates terminal every 100ms
```

#### 3. Transporter Selection Logic

```go
func createTransporter(config FactoryConfig) (interface{}, error) {
    switch config.Type {
    case TransporterBasic:
        return s3transport.NewTransporter(config.S3Client, config.S3Config), nil

    case TransporterStaging:
        t := s3transport.NewStagingTransporter(config.S3Client, config.S3Config)
        if config.EnableOptimization {
            // Enable all optimization features
            t.EnableAdaptiveStaging()
            t.EnableChunkPrediction()
            t.SetCongestionControl(config.CongestionControl)
        }
        return t, nil

    case TransporterAdaptive:
        // Similar pattern...

    case TransporterOptimized:
        // Similar pattern...
    }
}
```

## Architecture Decisions & Rationale

### Decision 1: Reuse LocalArchiver Pattern

**Rationale:**
- LocalArchiver is battle-tested in GhostShip production deployments
- Already integrates correctly with all transporter types
- Has worker pools, retry logic, progress callbacks built-in
- Avoids reinventing the wheel

**Alternative Considered:** Build CLI-specific archiver from scratch
**Rejected Because:** Unnecessary duplication, higher risk of bugs

### Decision 2: Staging Transporter as Default

**Rationale:**
- Best overall performance in benchmarks
- Includes deduplication (saves bandwidth/costs)
- Adaptive staging reduces memory pressure
- Chunk prediction optimizes for network conditions

**Alternative Considered:** Basic transporter as default
**Rejected Because:** Defeats purpose of CargoShip's advanced features

### Decision 3: Enable All Optimizations by Default

**Rationale:**
- Users expect CargoShip to "just be fast"
- Advanced users can disable with --no-optimization
- Matches "PhD not required" philosophy

**Alternative Considered:** Require explicit --enable-optimization
**Rejected Because:** Most users would never enable it

### Decision 4: Support Multiple Upload Modes

**Rationale:**
- Directory archive (default) - Best for datasets
- Single file upload - Simple use case
- Individual files (--no-archive) - Flexibility for mixed workloads

**Alternative Considered:** Archive-only mode
**Rejected Because:** Reduces flexibility, forces unnecessary archiving

### Decision 5: Eliminate Local Archive Creation

**Rationale:**
- Streaming is faster (no write-to-disk delay)
- Saves disk space (especially for TB-scale uploads)
- Core advantage of direct S3 integration

**Alternative Considered:** Keep two-stage upload (archive then upload)
**Rejected Because:** Slower, uses disk, defeats project purpose

## Appendix: Code Examples

### Example 1: Basic CLI Usage

```bash
# Default (staging transporter, all optimizations)
cargoship upload /data s3://bucket/dataset

# Specify transporter
cargoship upload /data s3://bucket/dataset --transporter adaptive

cargoship upload /data s3://bucket/dataset --no-optimization

# JSON output
cargoship upload /data s3://bucket/dataset --json-output
```

### Example 2: Factory Usage in Code

```go
// Create transport layer
factory := transport.NewFactory(transport.FactoryConfig{
    Type: transport.TransporterStaging,
    S3Config: s3cfg,
    S3Client: s3Client,
    EnableOptimization: true,
    CongestionControl: "bbr",
    EnableStaging: true,
    EnablePrediction: true,
    EnableBDP: true,
})

transporter, err := factory.CreateTransporter()
if err != nil {
    return fmt.Errorf("failed to create transporter: %w", err)
}

// Create streaming archiver
archiver := cli.NewStreamingArchiver(cli.ArchiverConfig{
    Transporter: transporter,
    SourceDir: "/data",
    Destination: "s3://bucket/dataset",
    Compression: "zstd",
    CompressionLevel: 3,
    Progress: progressTracker,
})

// Execute upload
result, err := archiver.ArchiveDirectory(ctx)
```
